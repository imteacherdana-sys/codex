# 모션 문법 — 코드깎는노인 기법 × 단아쌤 디자인 시스템

레퍼런스에서 가져오는 것은 **연출 원리**다. 다른 채널의 로고·캐릭터·책상 세트 같은 고유 디자인은 따라 하지 않는다.
모든 장면은 단아쌤 Tech Dark 톤(`tokens.json`)으로 만든다.

## 1. 원리 7개

| # | 원리 | 레퍼런스 장면 | 단아쌤 규칙 |
|---|---|---|---|
| P1 | **고정 무대** | 책상 3대 세트를 영상 내내 재사용 | 영상 1편마다 `Stage` 하나를 정해 비교·라운드 장면에서 계속 쓴다. 무대는 그대로 두고 내용만 바꾼다 |
| P2 | **스포트라이트** | 말하는 대상의 조명만 켜짐 | 지금 말하는 대상만 100% 밝기 + 고유색 글로우, 나머지는 35% 밝기 |
| P3 | **비우기 강조** | 검은 화면에 로고 하나 | 전환점 직전에 `EquationCard`로 요소 1개만 보여준다 |
| P4 | **드로우온** | 점 → 선 → 면 채우기 | "만들어지는 과정"을 설명할 때 선이 먼저 그려지고 색이 나중에 찬다 |
| P5 | **겉과 속** | 결과물 위에 반투명 코드 + 라벨 | 결과 화면 위에 원재료(프롬프트·데이터)를 30% 불투명도로 겹치고 라벨 2개를 단다 |
| P6 | **로드맵 선공개** | 코르크보드 폴라로이드 6장 | 1~2분 안에 `RoadmapBoard`로 오늘의 미션 수를 보여주고, 각 파트 시작에 `RoundCard`를 띄운다 |
| P7 | **3박자 키워드** | "붓 없이 / 이미지 없이 / 코드만으로" | 핵심 조건은 3개 묶음으로 시간차(8프레임 간격) 등장 |

알렉스 영상에서 더할 원리:

| # | 원리 | 단아쌤 규칙 |
|---|---|---|
| P8 | **실습 프롬프트 카드** | 시청자가 캡처해서 쓸 수 있는 프롬프트를 `PromptCard`로 3~4초 띄운다. "실습 프롬프트 n/N" 표기, 같은 내용은 설명란에도 넣는다 |
| P9 | **흐름도 하이라이트** | 단계를 말할 때 해당 박스만 라임으로 켠다 (`FlowSteps` 순차 강조) |

## 2. 컴포넌트 사전

기존 컴포넌트는 `danasam-tech-explainer`(긴 설명 장면)와 `danasam-motion-inserts`(4~6초 인서트)에 있다.
새로 만들 컴포넌트에는 **신규** 표시를 했다. 모든 PIP 장면 컴포넌트는 `contentArea` 안에만 그린다.

| 컴포넌트 | 출처 | layout | 길이 | 쓰는 순간 | 원리 |
|---|---|---|---|---|---|
| `Stage` | **신규** | PIP | 비트 길이 | 비교 대상 2~3개를 고정 무대에 세움 (받침대 + 고유색 글로우) | P1, P2 |
| `Spotlight` | **신규** | PIP | 비트 길이 | `Stage` 안에서 대상 하나만 켜기 | P2 |
| `EquationCard` | **신규** | CARD | 2~4초 | "A = B" 한 줄 요약, 전환점 | P3 |
| `DrawOn` | **신규** | PIP | 4~8초 | SVG 경로를 선 → 면 순서로 그림 | P4 |
| `OverlayLabel` | **신규** | PIP | 4~6초 | 결과 이미지 + 반투명 원재료 + 라벨 2개 | P5 |
| `RoadmapBoard` | **신규** (`MissionChecklist` 확장) | CARD | 6~10초 | 오늘의 미션 전체를 카드 N장으로 미리 보기 | P6 |
| `RoundCard` | **신규** | CARD | 2~3초 | "MISSION 02 / 05" + 미션 제목 | P6 |
| `PromptCard` | **신규** | CARD | 3~4초 | 실습 프롬프트 n/N | P8 |
| `KeywordTriplet` | **신규** | PIP | 3~4초 | 키워드 3개 시간차 등장 | P7 |
| `HookSplit` `TitleOrbit` `CardsRow` `CompareLR` `Keyword` `ChecksList` `Bubbles` `Rework` `CostBreak` `EndCard` 외 | tech-explainer | PIP | 비트 길이 | 기존 정의 그대로 | — |
| `CountUp` `KeywordHighlight` `CompareTable` `MissionChecklist` `FlowSteps` | motion-inserts | PIP | 4~6초 | 기존 정의 그대로 | P9 (`FlowSteps`) |

**기존 컴포넌트를 PIP에 쓸 때 고칠 점:** 지금은 화면 가운데(x=960) 기준으로 그린다.
`contentArea` 기준(중심 x=740, 폭 1320)으로 바꾸는 `safeArea` prop을 추가해야 한다. 이 작업이 S8의 첫 번째 개발 과제다.

## 3. 빈도·리듬 규칙

| 규칙 | 값 | 근거 |
|---|---|---|
| 말만 이어지는 최대 길이 (FACE 연속) | 20초 | 세진 v1.2 §6 (20~30초) |
| 화면 변화 간격 (훅 구간 0:00~0:30) | 2~5초 | 코드깎는노인 도입부 |
| 화면 변화 간격 (본론) | 6~15초 | — |
| 인서트 개수 | 1분당 1~2개 | motion-inserts |
| `EquationCard` | 개념 하나 설명이 끝날 때마다 1개, 영상당 최대 6개 | P3 |
| `RoadmapBoard` | 1:00~2:00 사이에 1회 | P6 |
| `PromptCard` | 영상 성격이 실습형일 때만, 파트당 최대 1개 | P8 |
| 같은 컴포넌트 연속 사용 | 금지 (`RoundCard`, `Spotlight` 제외) | motion-inserts |
| 폭죽(burst) 이모지 | 성과·완료 장면에만 | motion-inserts |

## 4. 도입부 0:00~2:00 표준 구성

코드깎는노인의 "누가·무엇을·왜·몇 판" 구조를 단아쌤 얼굴 진행에 맞게 바꾼 기본형이다. 작가는 이 틀을 기본으로 쓰고, 세진 v1.2의 "결과 선공개" 원칙과 충돌하면 결과 선공개를 우선한다.

| 시간 | 비트 역할 | layout | 컴포넌트 |
|---|---|---|---|
| 0:00–0:05 | 결과 선공개 또는 구체적인 고민 | FACE → PIP | `HookSplit` 또는 결과 화면 |
| 0:05–0:15 | 오늘의 약속 (얻는 것) | FACE | 로워서드 키워드 |
| 0:15–0:30 | Before → After 대비 | PIP | `CompareLR` / `Rework` |
| 0:30–0:45 | 조건 3박자 | PIP | `KeywordTriplet` |
| 0:45–1:30 | 등장 도구·개념 소개 | PIP | `Stage` + `Spotlight` |
| 1:30–1:45 | 개념 요약 | CARD | `EquationCard` |
| 1:45–2:00 | 오늘의 미션 로드맵 | CARD | `RoadmapBoard` → `RoundCard` 01 |
