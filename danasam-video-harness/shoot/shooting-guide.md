# 촬영 가이드 — 상반신 + 프롬프터 낭독

목표: 편집 에이전트가 **사람 손 없이** 테이크를 고르고 컷을 자를 수 있는 원본을 만든다.

## 1. 카메라·화면

| 항목 | 기준 | 이유 |
|---|---|---|
| 해상도 | 4K(3840×2160) 30fps, 가로 | PiP용으로 4:5를 잘라도 화질이 남는다 |
| 구도 | 가슴 위 상반신, 얼굴을 **화면 가운데**에 | PiP 크롭(4:5)과 FACE 풀화면을 같은 원본으로 쓴다 |
| 머리 위 여백 | 화면 높이의 10~15% | PiP에서 정수리가 잘리지 않게 |
| 렌즈 높이 | 눈높이 | — |
| 프롬프터 | 렌즈 바로 아래 또는 렌즈 앞 반사형 | 시선이 렌즈에서 벗어나면 PiP에서 바로 티 난다 |
| 배경 | 단색 또는 어두운 톤, 움직이는 것 없음 | PiP가 Tech Dark 배경 위에서 튀지 않게 |
| 의상 | 무늬 없는 단색. 라임·보라색은 피함 | 브랜드 강조색과 겹치지 않게 |
| 조명 | 얼굴 정면 소프트 라이트 + 배경과 분리되는 뒷빛 | — |
| 노출·초점 | 수동 고정 (자동 노출·자동 초점 끔) | 컷마다 밝기가 바뀌면 이어 붙인 티가 난다 |

## 2. 오디오

- 핀마이크 또는 근접 마이크, 48kHz, 피크 −12dB 근처.
- 촬영 시작 직후 **10초 동안 말하지 않고 가만히 있기** (방 소음 샘플 + 얼굴 위치 측정용).
- 에어컨·냉장고 소음은 끈다.

## 3. 읽는 방법 (편집 자동화를 위한 약속)

| 약속 | 방법 |
|---|---|
| 비트 단위로 읽기 | 프롬프터의 `[B012]` 한 덩어리를 한 호흡으로 읽고, 다음 비트 전에 **1초 쉰다** |
| 틀리면 | 그 비트를 처음부터 다시 읽는다. 앞에 **박수 한 번** 또는 "다시"라고 말한다 → 에이전트가 앞 테이크를 버린다 |
| 마음에 안 들면 | 똑같이 다시 읽는다. 에이전트는 **마지막 완주 테이크**를 고른다 |
| 애드리브 | 해도 된다. 자막은 실제로 말한 대로 들어간다. 단 숫자·제품명은 원고대로 읽는다 |
| 표정·제스처 | FACE 비트에서만 크게. PIP 비트는 얼굴이 작으니 고개 끄덕임 정도면 충분하다 |
| 파트 나누기 | 파트마다 파일을 나눠도 되고 한 번에 찍어도 된다. 파일명은 `A01.mp4`, `A02.mp4` 순서 |

## 4. 화면 녹화 (RECORD 비트)

- `record-list.md`의 순서대로, 파일명 `R{beat_id}_{설명}.mp4`.
- 1920×1080 이상, 마우스 커서 보이게.
- 시작 전 2초, 끝난 뒤 2초는 손대지 않고 가만히 둔다 (편집 여유).
- 실제 계정·고객 정보·결제 정보가 보이는 창은 닫거나 합성 데이터로 바꾼다.

## 5. 넘기기

- 원본을 run 폴더의 `footage/`에 올리고 "촬영 끝"이라고 말하면 S6이 시작된다.
- 못 찍은 비트가 있으면 비트 번호만 알려준다. 에이전트가 그 비트를 PIP/CARD로 대체할 수 있는지 판단한다.
